Warm-Up · No Screens · 10 min

20 Questions: could a "rule follower" win this game?

Try It — Partner Game

One partner thinks of an animal. The other asks only yes/no questions to guess it in 20 tries or fewer.

Think About It

What if the guesser could only react to specific words like "has fur" or "lives in water"? Would a fixed list of rules be enough?

Big Idea: A chatbot that only reacts to keywords is playing a version of this exact game — it just checks your words against a list of rules it already knows. That's what we build today.

Mini-Lesson — Part 1

What actually makes a chatbot "talk"?

Four ingredients, one conversation

1 input() — listen to the human
2 if/elif/else — decide what to say
3 lists — store keywords & replies
4 functions — organize the whole chat

A tiny live example

hi there!
Hello! I'm PyBot. Ask me anything!
what's your name
I'm PyBot, a simple Python chatbot.

This is a rule-based chatbot: it checks your typed words for keywords like "hi" or "name," then picks a pre-written reply. No learning happens — we wrote every rule.

Mini-Lesson — Part 2

The trick: check for keywords inside a sentence

The in keyword searches text

"hello" in "well hello there"
# → True (found it inside!)

Python doesn't need the exact sentence — just the keyword somewhere inside it.

Always lowercase first!

msg = input("You: ").lower()
if "hello" in msg:

"HELLO", "Hello", and "hello" should all match — .lower() makes that happen every time.

Question for later: What happens if a message contains two keywords at once, like "hi, how are you"? Which rule wins?

Mini-Lesson — Part 3

Functions: wrapping our rules in a box

Without a function — messy

Every time we want a reply, we'd copy the same if/elif block over and over. Repetitive and easy to break.

With a function — tidy

def get_reply(msg):
  if "hi" in msg:
    return "Hello!"
  else:
    return "Hmm?"

Now we can call get_reply(msg) as many times as we want inside our loop. One box of rules, reused every turn — that's why real programs use functions everywhere.

AI Moment

Phase 3 · Sessions 15–20

Rules we wrote vs. patterns a model learned

Our chatbot today

Follows rules WE wrote: "if 'hello' is in the message, say hi back." Every response is something a human typed in advance. No surprises, fully explainable.

A real chatbot (LLM)

Predicts the next word using patterns learned from billions of examples of text. Nobody wrote a rule for every reply — it was trained, not programmed.

Crisp contrast: our bot can only say what we told it to say. An LLM can say things nobody ever typed — because it learned the pattern of language, not a fixed list of answers.

Guided Build — Step by Step (20 min)

Build: A Keyword Chatbot

Click each step to reveal the code — then try messages on the right and watch the bot decide which rule fires.

Step 1 — Greet the human

print("Chatbot: Hi! Type 'bye' to exit.")

Step 2 — Start a loop & get lowercase input

while True:
  msg = input("You: ").lower()

Step 3 — Check for the exit word first

if "bye" in msg:
  print("Goodbye!"); break

Step 4 — Add keyword rules with elif

elif "hello" in msg or "hi" in msg:
  print("Hi there!")
elif "name" in msg:
  print("I'm PyBot!")

Step 5 — Catch everything else

else: print("I don't understand yet.")

Notice: Python checks rules top to bottom and stops at the first match — try "bye" last to see it end the chat.

Stretch Skill · random Module

Make replies feel less repetitive

Store several replies in a list

import random

greetings = ["Hi!", "Hey there!", "Hello, friend!"]

Pick one at random each time

if "hi" in msg:
  print(random.choice(greetings))

Same rule, different reply each run — the chatbot still isn't "learning," it's just choosing randomly from a list we wrote. Still 100% rule-based.
