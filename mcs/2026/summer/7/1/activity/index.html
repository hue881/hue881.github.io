🧠 Part 1 · Warm-Up (10 min)
Think First — Before You Touch the Keyboard
❓ Three Questions, No Screens

Answer honestly. You’ll use these answers all class long.

1. What is the ONE feature your project cannot work without? (If it vanished, would your project still make sense to a visitor?)

2. What happened the last time you ran your project — did it do what you expected?

3. If something broke, where do you think the problem might be hiding? (Hint: think about the last line that ran before things went wrong.)

Hold onto your answer to Question 3 — we’re about to learn exactly how to hunt that bug down.
💡 Part 2 · Mini-Lesson (15–20 min)
Bugs Are Not Failures — They’re Clues
🐛 Key Vocabulary

bug

A mistake in code that makes a program do something different from what you planned.

debugging

The process of finding and fixing a bug — one careful step at a time.

🦋 Fun fact: the word “bug” comes from a real moth found stuck inside a giant 1947 computer, causing it to malfunction! A bug never means you’re bad at coding — it means you’re one clue away from understanding your program better.
🔍 Our Debugging Method — Stop → Check → Find → Fix → Test
1 — Stop. Don’t panic or randomly change things. Take a breath.
2 — Check. What should happen? What is actually happening?
3 — Find. Look line by line where the behavior first goes wrong.
4 — Fix. Change one thing at a time — never many things at once.
5 — Test. Run it again. Did it work? If not, go back to Check.
Repeat until it works. That’s debugging!
💡 Print Debugging — the Fastest Fix in Your Toolkit

If you’re not sure a variable holds the value you expect, just ask the program to show you.

🐍 Python

score = 0
score = score + 1
print("score is now:", score) # check it!

🐱 Scratch

Drag a say [variable] for 2 secs block right after the spot you suspect is buggy. Or check the box next to a variable to watch it live on stage.

If your variable shows the wrong number, does that tell you WHERE the bug is, or just THAT there is one?

🔍 Know Your Enemy — Three Kinds of Bugs
🚫
Syntax Bug
The computer can’t understand your code — like a typo or missing colon. Program won’t run at all.
💥
Runtime Bug
Code is written correctly but crashes while running — like dividing by zero. Program starts, then stops suddenly.
🤔
Logic Bug
The program runs perfectly — it just does the wrong thing. Hardest to find: no error message!

Which of these three do you think is hiding in your project right now?

🕵️ Spot the Bug — Live Challenge

This tiny program is supposed to print numbers 1 through 5. Which line is buggy?

count = 1
while count < 5:
  print(count)
  count = count + 1

This is a logic bug! count < 5 stops the loop before printing 5 — it only prints 1, 2, 3, 4. Fix: change < to <=.
🔨 Part 3 · Guided Build (20 min)
Practice the Method — Together

Your teacher will model debugging a real bug on the board. Follow along and fill in each box as it happens.

📋 Watch & Record: Stop → Check → Find → Fix → Test
Stop — What was the bug the teacher demoed?
Check — What SHOULD have happened vs. what actually happened?
Find — Which line did the bug turn out to be hiding in?
Fix — What ONE change fixed it?
Test — Did it work the second time?
🎯 Notice: the teacher never changed more than ONE thing before testing again. That’s the whole secret.
💃 Movement Break (5 min)
Bug Hunt Charades
🕵 Act It Out

Stand up! Your teacher calls out a bug type — act out how you’d react.

  • “Syntax Bug” → freeze completely, arms crossed (nothing runs!)
  • “Runtime Bug” → walk normally, then suddenly collapse
  • “Logic Bug” → keep walking calmly but in the wrong direction
  • “Fixed!” → jump and cheer

    • Which bug type was the funniest to act out, and why?

    🛠 Part 5 · Open Build (30–40 min)
    Find Your Tier and Build!

    Today’s priority order for everyone: 1) Get your core feature running end-to-end, even if rough. 2) Use Stop→Check→Find→Fix→Test the moment something breaks. 3) Run the AI fairness & clarity check below. Find your tier and dig in — then climb!

    Tier A — Foundations · Grades 1–3
    🆎 Goal: One feature runs from start to finish

    Work with your buddy. Focus on making ONE thing work reliably — not adding anything new today.

    Your checklist:

  • I can point to my ONE must-have feature
  • I ran it and watched what happened
  • I used the say [ ] for 2 secs trick to check a value

    Buddy tip: One person reads the code out loud, the other watches the screen. Switch jobs after each bug!
    Tier B — Core · Grades 3–5
    ✅ Goal: Core feature working + first fairness check

    Get your must-have feature running end-to-end, apply the 5-step method to any bug you hit, then check your AI part for fairness.

    Your checklist:

  • Core feature runs start to finish
  • Used print/say debugging at least once
  • Identified the bug type (syntax/runtime/logic)
  • Fixed at least one real bug using Stop→Check→Find→Fix→Test
  • Ran the AI fairness & clarity check (below)

    • 🤖 AI Fairness & Clarity Check

  • FAIR: Works for everyone, not just my test cases
  • CLEAR: A stranger wouldn’t think it’s magic
  • TESTED: Tried an input I never tested before
  • CLARITY: No one could misunderstand what it decides

    • What bug did you find & fix?

    Tier C — Accelerated · Grades 6–9
    🟣 Goal: Core feature solid + edge cases + fairness audit

    Beyond making it work, actively try to break your own project with unusual inputs, then document and fix what you find.

    Your checklist:

  • All Tier B goals complete
  • Tried at least 2 unusual/edge-case inputs on purpose
  • Classified each bug found (syntax/runtime/logic)
  • Used print debugging to trace a variable's value over time
  • Full AI fairness & clarity audit written up (below)
  • Helped a classmate debug using the 5-step method

    • Think through:

    What edge-case input broke (or almost broke) your project?

    If your AI part isn’t fair yet, what specifically would you change?

    Stretch: Write your edge cases down as a mini “test list” you can rerun tomorrow during Feature Freeze — professional programmers call this regression testing.
